# Architecture

Speedcubing Assistant is **one self-contained HTML file**. No build step, no
framework, no dependencies except Google Fonts (optional — the page degrades to
system fonts). Everything below lives in `index.html`: one `<style>` block and one
`<script>` block, roughly 43 KB in total.

Read this before changing anything. Two mechanisms are unusual and will bite you
otherwise: the page **builds its own DOM from a string**, and user edits are
**baked back into the source** as a comment-delimited JSON blob.

---

## 1. Boot sequence

```
<body><div id="app"></div></body>
   ↓
SCRIPT_SRC   = document.currentScript.textContent   (the script reads itself)
SKELETON     = string containing the page's static markup
HEADBITS     = string containing the <head> tags
BAKED        = /*BAKED*/ {...} /*END*/  — user formulas/status baked in, or null
   ↓
document.getElementById("app").innerHTML = SKELETON
   ↓
DATA → render case rows into #oll and #pll
   ↓
localStorage + (optional) Claude account → loadAll() → update() per case
   ↓
tInit()  — timer
applyTheme(), menus, service worker
```

### Why SKELETON is a string

The **Download offline copy** feature regenerates a complete, standalone HTML file
at runtime (`buildPage(algs)`): it takes `SCRIPT_SRC`, swaps the `/*BAKED*/…/*END*/`
region for the user's current formulas, and reassembles
`HEADBITS + <style> + <script>`. For that to work, the markup must exist as data
inside the script rather than as parsed DOM.

**Consequence:** to change the page's static markup you edit the `SKELETON`
string literal, not a `<body>` you can see. It is JSON-encoded, so quotes are
escaped. The practical way to edit it is: decode with `JSON.parse`, modify, re-encode
with `JSON.stringify`.

## 2. Data model

### `DATA` — the case catalogue

```js
DATA = {
  oll: { title, sub, steps: [ { n, label, mask, cases: [...] } ] },
  pll: { ... }
}
```

Each case is a tuple:

```js
["pll-head", "Headlights", "L' U' L U L F' L2 U L U L' U' L F", "67%"]
//  id         display name   default formula                     probability
```

* **id** — stable key used by localStorage, the baked blob, and `data-id` in the DOM.
  Never rename an id without migrating stored data; the user's edits would be orphaned.
* **mask** — per *step*, decides how the diagram is coloured (see §4).
  `"edges"` | `"oll"` | `"corners"` | `"full"` | `"f2l"`.
* **probability** — a display string only; nothing computes with it.

A fifth historical slot existed for an alternative formula (`_alt` keys). The
rendering code still tolerates it but no case ships one.

### Cube state

A cube is a flat array of **54 sticker objects**:

```js
{ p: [x,y,z],   // current position of the cubie this sticker is on
  n: [x,y,z],   // outward normal — which way the sticker faces
  f: "U",       // the sticker's colour, as a face letter (never changes)
  h: [x,y,z] }  // home position, for tracking where a piece belongs
```

Coordinates are −1/0/+1. `y=+1` is the top layer. `NORM` maps a face letter to its
normal vector; `COL` maps it to a hex colour.

This representation makes the two things the app needs cheap: *where is this
sticker now* (p, n) and *where should it be* (h, f).

## 3. Move engine

| Function | Purpose |
|---|---|
| `parse(str)` | `"R U2 R'"` → `[["R",1],["U",2],["R",-1]]`. Accepts `RLUDFB`, slices `MES`, wide `rludfb` and `Rw` form, rotations `xyz`, modifiers `'` and `2`. Brackets are stripped. Throws on unknown tokens. |
| `MV` | move table: `[axis, layerTest, baseQuarterTurns]`. Axis 0=x, 1=y, 2=z. `layerTest(coord)` selects which slices move — this is how wide moves and rotations fall out of the same code. |
| `apply(st, moves)` | mutates a state in place |
| `rot(v, ax, q)` | rotate a vector by quarter turns |
| `invert(moves)` | reverse order, negate each |
| `fmt(moves)` | back to a string |
| `mirror(str)` | left↔right mirror: swap R/L and r/l, negate everything except M and x |
| `orientFix(moves)` | if a formula ends with the cube rotated (e.g. an A-perm starting with `x`), returns the rotation moves that put U back on top. This is why formulas with rotations still render correctly. |

### The central trick

**A case diagram is generated by applying the formula's inverse to a solved cube.**

```js
const st = solved();
apply(st, invert(parse(formula)));
```

The result *is* the position the formula solves. Formula and picture therefore
cannot drift apart — edit a formula and the diagram follows. There is no stored
case definition to keep in sync.

For PLL, `update()` additionally tries all four AUF turns and keeps the one that
moves the fewest pieces, so the diagram shows the case as you would actually hold
it; any leftover turn is reported as "Finish with U".

## 4. Rendering

### `draw(st, mask)` → SVG string

Draws the top layer from above, in a 100×100 viewBox: a 3×3 grid of U-facing
stickers plus a rim of side stickers around it. Front is at the bottom.

`colour(sticker, mask)` greys out whatever is irrelevant to the step:

| mask | shows in colour |
|---|---|
| `edges` | top-layer edges only (OLL step 1) |
| `oll` | any sticker whose colour is U (OLL step 2) |
| `corners` | corners only (PLL step 1) |
| `full` | everything (PLL step 2) |
| `f2l` | the front-right corner + edge pair only (legacy; no cases use it now) |

### `arrows(st, mask)`

Compares `p` to `h` for every top-layer piece and draws an arrow for each
displaced one. Mutual swaps get a double head; 3-cycles get single heads.
Pieces belonging to the *other* sub-step (edges during the corner step, etc.)
are drawn thinner, dashed and faded — "secondary" arrows.

### `update(li, id, mask)`

Per case row: parse → build state → `draw` → write SVG into `.pic`, resize the
textarea, and set the status message. Validation branches:

* parse error → the message
* `checkF2L` fails → "Breaks the first two layers"
* `isSolvedLL` → "Does nothing to the last layer"
* leftover AUF → "Finish with U"

Everything else yields an empty message. **There is no stored "expected" answer** —
validation is structural, not a lookup.

## 5. Storage

Three independent localStorage keys. Nothing is ever sent anywhere except the
optional Claude sync (§6), which only exists in the Claude-hosted build.

| Key | Contents |
|---|---|
| `twolook-algs-v1` | `{ algs: {id: formula}, status: {id: "learning"\|"learned"}, shut: {id\|stepKey: 1}, at: epoch_ms }` |
| `twolook-times-v1` | `{ times: [{ms, scr, plus2, dnf, at}], shut: bool, insp: bool }` — capped at the last 300 |
| `twolook-theme` | `"auto"` \| `"light"` \| `"dark"` |

Only **changed** formulas go into `algs`; a value equal to the default is deleted,
so `Reset` and future default changes behave predictably.

`shut` holds collapse state for both individual cases (by case id) and groups
(by `side + step number`, e.g. `"oll1"`).

### The BAKED blob

```js
const BAKED = /*BAKED*/{"oll-sune":"L' U2 L U L' U L", ..., "__status":{...}, "__shut":{...}}/*END*/;
```

Defaults resolve as `BAKED[id] || DATA's formula`. Two writers produce it:

* **Download offline copy** — `buildPage(current())` regex-replaces the region.
* **Save edits into the page** (Claude build only) — same, then republishes.

**If you hand-edit `index.html`, leave this region alone** unless you intend to
discard the user's edits. The comment markers are the contract; the regex is
`/\/\*BAKED\*\/[\s\S]*?\/\*END\*\//`.

## 6. Claude-hosted extras (absent in the GitHub/PWA build)

The hosted artifact may declare runtime capabilities and then uses, guarded by
`if (window.claude?.use)`:

* `db` + `user` — syncs the `twolook-algs-v1` payload to `data/users/<id>/algs`,
  last-write-wins by the `at` timestamp.
* `artifact` — the **Save edits into the page** button, shown only to the owner.
* `downloads` — native file save; falls back to a Blob + `<a download>` elsewhere.

All of this is inert in the self-hosted copy: `window.claude` is undefined, the
status line reads "Saved in this browser only", and the Save button stays hidden.
**Never use `alert`/`confirm`** — artifact frames block modals. The page uses a
two-step button for destructive actions and the `#sync` line for messages.

## 7. Timer

State machine in `beginHold` / `endHold` / `stopTimer`, driven by the space bar
(ignored while a textarea has focus) and by touch/mouse on the clock.

```
idle ──hold≥300ms──▶ ready ──release──▶ run ──any press──▶ idle (time recorded)
  └─with inspection─▶ insp ──hold/release──▶ run
```

Inspection: 15 s countdown; overrun up to 2 s attaches `plus2`, beyond that `dnf`.

`scramble(20)` emits random moves, rejecting a move on the same axis as the
previous one and a repeat of the face two back. It is **random-move, not
random-state** — no solver is embedded. Face distribution is uniform (verified
over 400k moves).

Statistics follow WCA rules: `avg(list,k)` drops the best and worst of the last
*k* and means the rest; `eff(r)` applies +2 and maps DNF to `null`; two DNFs in a
window make the average DNF.

## 8. Layout and CSS

Single `<style>` block, custom properties on `:root`, dark theme defined three
times so it works in all combinations:

```css
:root { --bg: #fff; ... }                                   /* light */
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { ... } }
:root[data-theme="dark"] { ... }                            /* explicit */
```

Three layouts:

* **Desktop** — `.layout` flex: 250px timer sidebar (sticky) + two-column `.grid`.
* **Compact, ≤620px** — timer becomes a sticky bar at the top (CSS grid with named
  areas), toolbar collapses into a **Menu** dropdown, times list collapses behind
  **Times ▾**, OLL and PLL stay side by side with 46px diagrams.
* **Print** — hides timer, buttons, status circles and chevrons, forces light
  colours regardless of theme, opens collapsed sections, two columns, fits one page.

Collapsing: `.case.shut` and `.step.shut` hide their content via CSS; JS only
toggles classes and persists the flags. Textareas are auto-sized by `fit()`, which
**must** be re-run when a container becomes visible — a textarea measured while
`display:none` reports zero height (this caused the "collapsed group is empty" bug).

## 9. PWA shell (self-hosted build only)

| File | Role |
|---|---|
| `manifest.json` | name, icons, `display: standalone`, theme colour |
| `sw.js` | cache-first service worker, `CACHE = "cubing-v1"` |
| `icon-192/512/512-maskable.png` | icons |

**Bump `CACHE` on every `index.html` change**, otherwise installed devices keep
serving the old cached copy. The page listens for `updatefound` and writes
"New version ready — reload to update" into `#sync`.

## 10. How to make common changes

**Add a case** — append a tuple to the right `steps[].cases` array in `DATA`.
Nothing else: the row, diagram, validation and storage key all derive from it.
Pick an id that no existing case uses.

**Change a default formula** — edit it in `DATA`. Users who edited that case keep
their version (it lives in `algs`); everyone else sees the new default. If a
`BAKED` blob is present it still wins, so clear that case's key there too.

**Add a new section (e.g. F2L)** — add a top-level key to `DATA`, add a
`<section class="col" id="...">` to `SKELETON`, extend the
`for (const side of ["oll","pll"])` loop, add a `mask` branch in `colour()` and a
validation branch in `update()`, and widen `.grid`'s column count.

**Change the markup** — edit the `SKELETON` string (see §1).

**Change validation** — `update()` for the per-case message; `checkF2L` /
`isSolvedLL` are the structural predicates.

---

## 11. Invariants worth preserving

1. Diagrams are always derived from formulas. Never hard-code a case picture.
2. Case ids are permanent keys. Renaming one orphans stored user data.
3. The `/*BAKED*/…/*END*/` markers must stay intact and parseable as JSON.
4. `SKELETON`, `HEADBITS` and `SCRIPT_SRC` must remain sufficient to rebuild the
   whole file, or **Download offline copy** silently produces a broken page.
5. No `alert`, `confirm` or `prompt`.
6. No external runtime dependency beyond the optional web font.
7. Everything degrades: no `window.claude`, no service worker, no localStorage —
   the page still renders and works.

## 12. Testing

There is no test suite. The checks used during development were ad-hoc Node
scripts that `eval` the engine section out of `index.html`:

```js
const src = fs.readFileSync("index.html", "utf8");
let js = src.slice(src.indexOf("<script>\n") + 8, src.lastIndexOf("</script>"));
js = js.slice(js.indexOf("/* ---- cube model"), js.indexOf("/* ---- storage"));
eval(js + `/* your assertions here */`);
```

That gives you `solved()`, `parse`, `apply`, `invert`, `draw` and friends outside
the browser. Formula correctness was verified by building each case state and
confirming a reference algorithm solves it under some AUF. Playwright was used for
layout, persistence and offline checks.
